## Transition contracts

- **Cold Main Menu:** no persistent service set is created. The first gameplay scene creates it. Main Menu UI and its dormant popup are scene-lifetime.
- **New Game:** if any current or legacy save exists, Main Menu shows an overwrite confirmation. Cancel changes nothing. Confirm clears all run, relic/rebirth, item, skill, ordinary-currency and Ancient-currency state; preserves preferences; creates a new run ID/seed; starts level 1/stage 1 with starter equipment; atomically commits it; and replaces the backup with the new run so the old run cannot recover later.
- **Load Game:** the one-shot request is consumed once. Primary is parsed and fully validated in memory, then backup is attempted if needed. Runtime mutation occurs under a restoration guard. Gear/relic identity graphs, progression, skill, currencies, combat position, encounter, and checkpoint resources restore in dependency order. Failure returns to Main Menu without deleting either file.
- **Restart after death:** this remains a current-combat-level restart. It resets encounter kills, boss/death flags, enemy/player encounter resources and spawns a normal enemy while preserving combat level, XP/passives, inventory, equipment, currencies, relics and selected skill.
- **Return to Main Menu:** the gameplay scene destroys combat, actors, pickups and HUD. Persistent managers remain exactly once, but their player/zone/loot/death-menu/stat references are cleared. Save data is not deleted. A later New Game or Load Game binds only objects from the new gameplay scene.

## Static and event policy

`GamePersistence.loadRequested` is mutable static transition intent and is cleared by New Game or one consume. Singleton `Instance` fields represent their documented category and clear only when the authoritative owner is destroyed; duplicate owners never replace them. `BattleManager.InstanceChanged` and `CurrencyInventory.GearChanged` are static events: scene subscribers pair subscribe/unsubscribe in enable/disable or destroy paths. `GameManager` and `EquipmentManager` each subscribe once to `SceneManager` only after winning singleton authority and unsubscribe on genuine destruction. UI open flags clear on scene UI destruction. Read-only roll tables, regexes, and art/audio/sprite caches are application caches and intentionally survive scene transitions.

At each encounter spawn, `BattleManager` records the player's then-current life/mana and clears gauges while deterministic enemy generation uses the run seed plus combat position. Save captures that encounter-start checkpoint, not mid-hit resources. Load creates the same clean encounter at full enemy resources, clears statuses and presentation transients, then restores the recorded player life/mana. Inventory, equipment, currency, passive, skill, and relic mutations mark one dirty checkpoint; `GamePersistenceHost` coalesces them for two seconds. Crafting, encounter advancement, Rebirth, and explicit pause-menu exits save immediately.
