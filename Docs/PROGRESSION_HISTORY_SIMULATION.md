# Production progression history simulation

Open **Black-Cube → Balance Workbench → Loot / Itemization → Progression History**. Choose a target Player Level, History Mode, seed, and assumed Enemy Power, then run progression. Straight mode advances through the production ten-stage combat-level sequence. Target Farming adds designer-selected extra full clears. Manual mode records designer-entered rarity and boss counts but deliberately does not infer XP or historical item inventory. Seeded Stochastic mode samples rarity, drops, and currency with injected deterministic RNG; Expected mode integrates probabilities and explicitly omits legacy weighted currency entries.

The simulator reuses `PlayerProgression.RequirementAt` and `EnemyReward`, world stage resolution, production rarity weights, and configured loot budgets. It reports Player Level separately from Combat Level, actual encounter counts, rarity mix, boss kills, expected gear copies, and each ordinary currency. A level-10 smoke produced 55 encounters and 55 gear drops for seed 41001; that is a reproducible example, not a balance target. Dropped Item Level is capped by the production item system and each historical item retains its original level.

Assumptions are explicit: encounters are considered wins for the progression history; survivability belongs to Combat Lab and Full-Level Calibration. Enemy Power is a selected input until reference rows have been generated for the desired combat levels and rarities. At Combat Level 100 and above the present `PlayerProgression.EnemyReward` path yields zero because it calls `RequirementAt(combatLevel)` after the player-level cap. The tool reports that gap rather than inventing post-cap XP. Do not claim straight progression reaches Player Level 100 until that production rule is resolved.

After the history run, generate a historical inventory, optionally run shared-currency crafting, and compare crafted versus untouched gearsets. `REALISTIC_PLAYER_MODEL.md` explains the next steps and limits.
