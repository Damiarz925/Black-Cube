# Realistic player model: current implementation and boundaries

Open **Black-Cube → Balance Workbench → Loot / Itemization → Progression History**.
Choose a target Player Level, Straight or Target Farming, the number of extra complete clears, a seed, and Seeded Stochastic or Expected mode. **Run Progression** reports the production rarity mix, ten-stage combat-level sequence, XP, gear count, and currency acquisition. Player Level caps at 100; Combat Level extends to 360; dropped Item Level caps at 100. Items keep the level at which they dropped.

The history uses `PlayerProgression.RequirementAt` and `EnemyReward`, production enemy-rarity spawn weights, `WorldProgression.Resolve`, and `EnemyLootProfile.RollConfigured`. It assumes every encounter is won. Seeded Stochastic includes legacy weighted currencies; Expected mode integrates rarity-weighted direct-rate currencies and explicitly warns that it omits legacy-weighted currencies. Enemy Power is a visible input until an explicit reference population exists. Manual mode records designer-supplied counts but does not infer XP or loot from them.

Important production-rule gap: `PlayerProgression.EnemyReward(combatLevel, ...)` uses `RequirementAt(combatLevel)`, which returns zero at combat level 100 and above. The history reports that limitation rather than fabricating later XP. Reaching Player Level 100 by straight progression therefore needs an explicit progression-design decision.

After running a history, select **Generate Ground-Loot Inventory**. This invokes production item-type weights, level-specific rarity rates, element and weapon selection, `ModManager` affix rolls, and weapon profiles with an injected deterministic RNG. It does not create a fixed number of items per slot. All generated items remain in the inventory result and can be exported to JSON.

**Run Expected Crafting** evaluates projects from the historical inventory and the one shared currency stock. Fast, Serious, and Deep modes sample respectively 2, 6, and 16 deterministic production craft rolls per legal action. Candidate shortlist sizes per slot are 8, 24, and all. The highest positive sampled build improvement is crafted with production rules and RNG. Every action respects Crafting Potential, spends one matching currency, and spends one Affix Focus only when the Prefix/Suffix constraint was selected. After every action the project ranking is recomputed against the current build. The initial Craftability table, action trace, spent currency, unused currency, and stopping reason can be exported. Fast defaults to a 12-action budget; this is an editable analysis budget, not an assertion that a player should only craft 12 times. Expected-mode fractional currency quantities are floored before spend so the model cannot borrow future currency.

**Use Expected Crafting** is on by default. Turn it off for the Ground Loot Only comparison. **Optimize Crafted Gearset** (or Ground-Loot Gearset) evaluates every retained item for candidate ranking, keeps a bounded diverse shortlist per slot, and searches complete eight-slot sets. It can value current Life, Armour, Fire, Cold, Lightning, and Void resistance deficits dynamically via enabled Player Build constraints. **Soft** adherence may accept a deficit; **Strict** requires every enabled final floor. No affix slot is reserved. Untouched items can beat crafted items in this final search.

**Optimize Gear + Passives** runs two bounded alternations of the whole-inventory gear search and production-legal passive allocation. Each passive pass starts from the same source/locked allocation, so the first pass does not permanently reserve points. Enabled defensive deficits influence passive choices as well as gear choices. This is a local search, not proof of a global optimum, and it does not yet model player decisions to craft after each individual encounter. Ground loot, currency, crafting, gear, and passives are deterministic for fixed production data, seed, settings, and objective. The selected build can be sent to Player Build for Combat Lab validation.

Player Build now exposes a `total_dps` objective and an analytical resource scheduler. It compares no skills, each skill alone, and both priority orders over a warmup plus sustained measurement interval. Auto-cooldown skills and queued attack replacements follow separate timing paths. Mana maximum, regeneration, on-hit recovery, costs, and cooldowns matter; insufficient Mana can make skipping a weak second skill optimal. This is a fast search estimate, not an enemy-specific DPS verdict: skill-specific ailment interactions, mitigation, and actual combat outcomes require Combat Lab validation.

**Player → Defense Calibration** can run the production nine normal encounters and boss. It carries Life and Mana between fights. The No-Recovery override suppresses renewable player Life healing only; it does not change Life, Armour, resistance, offense, Mana, or enemy recovery. Encounter-local Rage and buffs reset. This tool calibrates a supplied build; it does not invent final Life/Armour/recovery curves.
